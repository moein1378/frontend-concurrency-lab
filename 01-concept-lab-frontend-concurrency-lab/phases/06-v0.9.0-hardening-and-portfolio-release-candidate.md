## Local execution contract

1. `corepack enable`
2. `pnpm install --frozen-lockfile`
3. `pnpm seed` to restore deterministic assets and fixtures.
4. `pnpm dev` for the primary experience or `pnpm dev:all` only when this phase activates services.
5. `pnpm verify` before the phase may be tagged.

The phase must remain usable in fixture/local mode even when an optional hosted provider is unavailable.

## Live-demo state

GitHub Pages static demo using deterministic local simulators and MSW fixtures.

## CI/CD changes required in this phase

- Extend the CI matrix only for capabilities introduced in this phase.

- Run documentation links and secret scanning.

## Docker and service state

Not required. A tiny optional Hono latency fixture may run directly with Node; Docker is intentionally avoided for the primary workflow.

For this phase, containers are added only if a newly activated service cannot be represented reliably by a direct local command.

## Responsive and accessibility acceptance

- Apply the project decision: Adaptive desktop-first lab; usable on tablet, with phone mode limited to single-column experiment playback.
- New interactions must be keyboard reachable and expose visible focus.
- Touch targets are at least 44px where the phase includes mobile interaction.
- State, failure, and progress are never communicated by color alone.
- `prefers-reduced-motion` behavior is tested when motion appears.

## Test plan

- Unit tests for domain transitions and pure policies.
- Integration tests across the activated modules.
- At least one deterministic browser workflow covering the user-visible outcome.
- Failure-path tests for cancellation, retry, stale data, invalid inputs, or unavailable capabilities relevant to this phase.
- Snapshot/visual tests only for stable visual contracts, not dynamic telemetry.
